# 运行时与性能模型、崩溃隔离

应用程序 SDK 文档的一部分 — 请从 [README](../../README.zh-CN.md) 开始阅读。

## 10. 运行时与性能模型

SDK 的设计遵循一条规则：已安装但未打开的应用，持续的渲染开销应当实际为零。

### 安装时的工作

导入应用程序时会进行校验、清理和编译。编译后的包与桌面配置分开缓存。打开已安装的应用通常不会重复进行包清理。

### 资源懒加载

体积大的资源单独存储，只有在被引用时才会请求。一个带有许多图片的包，不会在应用程序启动时把它们全部解码或传输。

### 私有运行时通道

每个正在运行的应用程序都有一条专用的 `MessageChannel`。全局的 `window.message` 监听器只用于沙盒引导；正常的 API 通信走私有端口。

### 宿主负责的窗口合成

受管理的窗口共用一个宿主玻璃层。拖动窗口期间：

- 移动由指针捕获驱动；
- 视觉上的位移每个动画帧只做一次 `translate3d()` 更新；
- 最终的 `left/top` 几何位置在拖动结束时提交；
- 插件 iframe 暂时不再接收指针输入，这样指针划过它时不会吞掉宿主的拖动；
- 插件的 CSS 动画/过渡暂停；
- 应用程序窗口在移动时保持与系统窗口相同的磨砂玻璃；
- 指针移动几个像素之后拖动才开始，所以在标题栏上单纯点击不会改变任何东西。

### 不可见时挂起

应用会收到可见性变化的通知。在严格模式下，应用隐藏/最小化时，定时器不会继续执行高频工作。

### 给作者的建议

想让应用流畅：

- 只要可能就优先使用 `runtime: "native"`；
- 对 `transform` 和 `opacity` 做动画，而不是布局属性或大面积滤镜；
- 不要创建嵌套的、覆盖整个表面的背景模糊层；
- 使用事件驱动的更新，而不是常驻的轮询定时器；
- 更新已有的 DOM/控件状态，而不是销毁并重建整个视图；
- 把打包的位图缩放到实际显示的尺寸；
- 不可见时或宿主拖动窗口期间，暂停自定义渲染；
- 多个控件一起变化时，用 `macos.ui.batch()` 批量提交 Native UI 的改动。

## 11. 崩溃隔离

应用逻辑运行在 `plugin/app-runtime.html` 里，与新标签页主 JavaScript 上下文分开。未捕获的错误或未处理的 Promise 拒绝会报告给宿主。宿主会拆掉出错的运行时，并在该应用窗口中显示重新载入的界面。

因此，一个坏掉的应用程序无法让它失败的沙盒里的定时器和动画无限期运行下去，也不会终止桌面外壳或其他应用。
