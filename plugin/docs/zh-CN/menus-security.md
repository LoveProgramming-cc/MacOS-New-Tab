# 菜单、多开、安全级别与开发者工具

应用程序 SDK 文档的一部分 — 请从 [README](../../README.zh-CN.md) 开始阅读。

## 8. 应用程序专属菜单栏

应用可以声明菜单栏菜单：

```json
"menus": [
  {
    "title": "File",
    "titleKey": "menuFile",
    "items": [
      { "label": "New", "labelKey": "menuNew", "command": "new", "shortcut": "⌥⌘N" },
      { "separator": true },
      { "label": "Delete", "command": "delete", "danger": true }
    ]
  }
]
```

### 应用程序菜单

每个应用都会自动得到标准的应用程序菜单，位于菜单栏中以粗体显示的应用名称之下：**关于**（名称、版本、描述和权限）、**设置…**、**隐藏**、**隐藏其他**、**全部显示** 和 **退出**。窗口处理由宿主实现；应用对此无需做任何事。

**设置…** — 有自己设置界面的应用在清单中声明 `"settings": true`，并在收到 `settings` 事件时显示该界面：

```js
macos.on('settings', () => { settingsOpen = true; render(); });
```

没有 `"settings": true` 时，“设置…”会打开 系统设置 ▸ 应用程序，并定位到该应用所在的行（启动时打开、导出、卸载）。宿主不会生成按应用的偏好设置：语言选择、强调色或应用想让用户配置的任何其他东西，都要由应用自己构建。

你自己的其他条目放在 `appMenu` 中，它们作为普通的菜单命令送达：

```json
"appMenu": [ { "label": "Check for Updates…", "labelKey": "menuUpdates", "command": "updates" } ]
```

程序坞中没有图标却正在运行的应用，会出现在程序坞里应用程序的末尾；用户可以把那个图标拖到其他图标之间，或者使用其上下文菜单中的 **在程序坞中保留** 来留住它。

隐藏或最小化的应用继续运行（音频继续播放），并带着指示点留在程序坞中；点击程序坞图标可以把它带回来。应用通过 `visibilitychange` 得知。

### 多开（实例）

一个应用程序有一个窗口。再次打开它会显示那个窗口。

用户可以在 开发者 ▸ **应用程序多开** 中允许更多窗口：一个总开关、每个应用程序的数量上限，以及对每个应用程序而言是否可以多次打开、后续窗口是否共享其存储。这是用户设置，包不能请求它。允许之后，应用程序菜单和程序坞图标的上下文菜单中会出现 **新建窗口**。

每个实例都是独立的运行时：有自己的沙盒、状态和媒体播放器。`macos.storage` 和 `macos.files` 是：

- **共享**（默认）— 每个实例读写同一个存储池。实例不会被告知彼此的写入；打算这样运行的应用应当重新读取它需要的内容，而不是假定自己是唯一的写入者。
- **独立** — 实例 1 使用应用的存储池；实例 *n* 有自己的存储池，按该编号保存，所以第二个窗口下次打开时能找回自己的数据。

`macos.context.instance` 和 `macos.context.sharedStorage` 说明当前属于哪种情况。卸载应用程序会移除所有存储池。

同一应用程序的各个窗口可以互相告知发生了什么变化：

```js
await macos.instances.broadcast({ type: 'note-updated', id });           // 发给其他每个窗口；resolve 为送达的数量
macos.on('instancemessage', ({ from, message }) => {});                   // from：发送方的实例编号
const windows = await macos.instances.list();                             // [{ instance, self, front, title, sharedStorage }]
```

系统设置 ▸ **储存空间** 显示每个应用程序占用了多少 — 应用程序本身加上它的数据和文件 — 并让用户整体抹掉一个应用程序的数据（先关闭它的窗口；下次启动从空白开始）。更细的操作 — 移除未使用的文件、清除某一类内容 — 由应用程序在自己的设置中提供，就像“音乐”那样。那里的 **导出数据…** 会把一个应用程序存储的所有内容 — 每个存储池的键值存储和每个已存储的文件，外加一份 `data.json` 目录 — 保存为一个归档；**导入数据…** 用这样的归档替换该应用程序的数据（归档必须来自同一个应用程序）。两者都属于系统，不需要应用程序做任何事。

**哪种导出属于哪里。** 备份、恢复或迁移一个应用程序持有的 *全部* 内容是系统的工作（上面那两个按钮）：不要自己再做一个“全部导出”。应用程序自己的导出，针对的是 *用户心目中的一个单位，他会把它交给别人或别的程序* — 一个播放列表连同其中的歌曲、一本书、一份文稿 — 并采用在应用程序之外也有意义的格式。“音乐”可以导出和导入单个播放列表（`macos.archive`）和单首歌曲（`macos.files.export`）；整个资料库则在它的设置中指向 系统设置 ▸ 储存空间。

### 应用菜单

当该应用的窗口成为活跃窗口时，桌面菜单栏会切换为该应用的菜单，并且在窗口保持活跃期间，每个条目的 `shortcut` 都处于绑定状态。快捷键写作 `⇧⌘S`、`Cmd+Shift+S` 或 `Ctrl+S`；`⌘` 也匹配 Ctrl。快捷键至少需要 ⌘ / Ctrl / ⌥ 之一，浏览器为自己保留的组合键（`⌘T`、`⌘W`、`⌘N` 等）永远无法绑定。命令会送达应用沙盒：

```js
macos.on('menucommand', ({ command }) => {
  if (command === 'new') {
    // ...
  }
});
```

应用声明的是语义化的命令；它不操作菜单栏的 DOM。

## 9. 严格安全性

严格安全性是默认设置，并且按应用程序分别决定。

开发者模式中有 **关闭严格安全性**。这个开关默认关闭，打开它本身不会放宽任何东西：它只是让每个应用程序可以选择 **安全级别**（设置 → 开发者 → 应用程序安全性）— *严格* 或 *宽松*。用户没有设为“宽松”的应用程序保持严格。包不能要求某个级别，导入的配置也不能携带级别。

在严格安全性下放不下的包（太大、文件太多）会被拒绝。开关打开期间，则会询问用户是否以宽松方式安装这一个应用程序。

在严格模式下，宿主施加明确的限制：

- 当前的应用程序包格式必须是 `macos-app-package-v3`；
- 包 JSON 限制在约 2.5 MB 和 160 个虚拟文件以内；
- 入口 HTML/CSS/JavaScript 的大小有上限；
- Web App 的 HTML 不能带有可执行的 `<script>` 标签或内联的 `on...` 处理器；代码来自 `entry.script`；
- 内嵌的 `iframe`、`object`、`embed`、外部 `link` 和 `meta` 内容会被移除；
- 包内 HTML/CSS 中对外部 HTTP/HTTPS 资源的引用会被阻止；
- CSS 的 `@import` 会被移除；
- 包作者写的 `backdrop-filter` 和 `filter: blur(...)` 会被移除；请改用宿主/原生材质；
- 严格沙盒页面（`plugin/app-runtime-strict.html`）带有 Content-Security-Policy，不允许任何形式的网络连接，不允许嵌套框架，并且只从宿主为包资源发放的 `data:` / `blob:` URL 加载图片、字体和媒体。这才是真正的边界；它无法从脚本绕过；
- 作为一种提早出现、易于阅读的错误，直接的 `fetch`、XHR、WebSocket、EventSource、SharedWorker 和 `window.open` 也被替换成会抛出异常的函数；权限边界由声明的宿主 API 提供；
- `macos.fetch` 无法访问本机或私有网络地址；
- 网络请求的并发数受限；
- 宿主 API 调用限制为每个应用每秒 240 次（关闭严格安全性时为 1 200 次）；一次 `ui.batch` / 合并后的 `patch` 只算一次；
- worker 只能从 `blob:` 脚本创建，并继承同样的禁止联网策略；
- `setInterval` 被钳制到至少一个 16 ms 的帧，活跃定时器的数量有上限；
- 宿主拖动受管理窗口期间，或应用不可见时，定时器回调暂停；
- 沙盒无法访问新标签页的 DOM、其他应用的存储或 `chrome.*` 扩展特权；
- 应用程序崩溃与桌面外壳相隔离。

对于设为 **宽松** 的应用程序，包/资源/代码的限制会放宽，可能允许更重的 CSS/外部资源。它仍然在 Manifest V3 沙盒中执行，宿主 API 仍然要求声明权限。`macos.context.strictSecurity` 告诉应用程序它运行在两者中的哪一种之下。

更改应用程序的级别会关闭它的窗口；重新打开它，才会按新策略启动。

## 没有限制的应用程序

严格安全性关闭后（开发者 ▸ **关闭严格安全性**），会出现另一个开关：**没有限制的应用程序**。用户需要经过两次说明后果的确认才能打开它；它增加第三个安全级别 *不受限制*，之后由用户逐个赋予应用程序。它绝不会应用于所有应用程序，包不能要求它，导入的配置也不能携带它。

对于被选中的应用程序，宿主不再强制执行权限声明（所有 API 都可用）、存储和文件配额、对文件、响应和包的大小限制、速率限制、节点数限制，以及对本地和私有网络地址的阻止。应用程序仍然在其沙盒框架中运行。

## 开发者工具

开发者模式 ▸ **启用开发者工具** 会增加一个开发者工具窗口（苹果菜单，或开关旁边的按钮）。它关闭时不会记录任何东西。

| 面板 | 用途 |
| --- | --- |
| *（启动器）* | 开发者工具开启期间，启动台中会出现一个 **开发者工具** 应用程序（也出现在 访达 ▸ 应用程序 和聚焦搜索中）；它可以像其他应用一样保留在程序坞中。 |
| 应用程序 | **从文件夹载入…** 直接从源码目录安装应用（与 `plugin/tools/pack.py` 写出的包相同，只是在页面中构建），并在任何文件变化时重新载入 — 开发时不需要打包或导入。文件夹访问权在页面打开期间有效。**打包文件夹…** 和 **导出安装包** 写出可安装的 `<id>.macos-app.json` — 来自一个文件夹（按安装时的方式检查），或者来自已安装的包。针对每个应用程序的 **模拟条件**：显示语言、浅色/深色外观、窗口尺寸（清单中的最小值和默认值，以及常见尺寸）、显示缩放（75–200 %；应用会按相应更少或更多的点数布局，`devicePixelRatio` 随之变化）、被拒绝的权限、离线（`macos.fetch` 失败）、存储已满（`storage.set` 和文件存储失败）。**权限使用记录**：每项权限及其被使用的次数；未使用的和被拒绝的会突出显示。 |
| 控制台 | `macos.log` 的输出、未捕获的错误和崩溃、每次 API 调用及其参数、结果和耗时，以及（可选）宿主发送的事件和系统事件。**性能预算**：耗时超过一帧（16.7 ms）的界面更新（`ui.*`）会被标记，一秒内发出超过 90 次 API 调用的应用程序也会被标记。 |
| 界面检查器 | 原生应用的实时节点树，带有 id、尺寸和行数，并与节点上限对照；指向某个节点会在窗口中高亮它，点击则显示它的属性。**显示布局边界** 为每个节点描出轮廓。 |
| 存储 | 应用程序的键值条目（可作为 JSON 编辑）和已存储的文件，按存储池分列。 |
| 录制与回放 | 录制宿主发给应用程序的输入事件 — 控件事件、按键、菜单命令、聚焦搜索结果、状态项目和通知的点击 — 并以原始速度、×4 或尽可能快的速度回放，可选择在重新载入应用程序之后回放。改代码，回放，应用就回到你正在处理的状态。录制内容可以导出和导入为 JSON。 |
| 系统 | 帧率、长任务、DOM 大小；每个窗口及其状态、顺序和调整大小规则；每个桌面表面被重绘或跳过的次数；内部事件和配置保存。 |
| 配置 | 以树的形式显示规范化后的配置，可选择只显示与默认值不同之处；诊断信息导出。 |

开发者页面上的 **慢动作动画**（÷2、÷4、÷10）会放慢所有动画 — 窗口飞行、原生过渡、CSS 过渡 — 而不改变它们的行为。
