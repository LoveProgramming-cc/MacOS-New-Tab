# リファレンスアプリケーション

アプリケーション SDK ドキュメントの一部です — [README](../../README.ja.md) から読み始めてください。

## 12. リファレンスアプリケーション

### 計算機

読めるディレクトリと、1 ファイルの読み込み用パッケージの両方で含まれています。

```text
plugin/examples/glass-calculator/
  src/ui.json
  src/main.js
  locales/*.json
  assets/icon.png
  assets/delete.svg

plugin/examples/glass-calculator.macos-app.json
```

計算機は `runtime: "native"` のアプリです。デフォルトでダーク（`window.appearance`）で、「表示」メニューからライト、ダーク、システムの外観を選べます（`macos.window.setAppearance`）。キーパッドは `themechange` で描き直されます。キーパッドは、それぞれの色を持つ `shape: "circle"` ボタンの 4 列の `grid`、ディスプレイは 2 つの `text` ノードで、キーボードは `macos.on('keydown')` で扱います。恒久的にダークなウインドウを要求し、`⌘C` ショートカットが動く「編集」メニューを宣言しています。

### ミュージック

```text
plugin/examples/music/
  app.json
  src/ui.json
  src/main.js
  locales/*.json
  assets/icon.png
  assets/cover.svg

plugin/examples/music.macos-app.json
```

完全な `runtime: "native"` アプリケーションです。自分の曲を読み込み（ファイルピッカー、またはウインドウへのドラッグ）、埋め込まれたタグとカバーアートを使ってアーティスト別・アルバム別にブラウズし、プレイリストとプレイリストフォルダを整理し、各プレイリストにタイトルとカバー画像を付け、検索と並べ替え、シャッフルとリピート、再生キューの管理、そして書き出し — 1 曲を元のファイルとして、またはプレイリストを再び読み込める 1 つの `.zip` として — ができます。大きめのアプリのあるべき形を示しています。

- インターフェイス全体が 1 つの `view()` 関数で、`macos.ui.render()` で描画される。
- オーディオファイルはサンドボックスに入らない：`macos.files` にあり、`macos.audio` が再生する。
- カバーは `blob:<id>` の画像ソース。サイドバーは、セクションヘッダ、フォルダの開閉行、行ごとのメニューを持つ `plain` なリスト。曲のリストは、仮想化され、並べ替えでき、複数選択できる `list` で、`itemMenu` を持つ。
- ウインドウは `titlebar: "hidden"` で、ルートは `split`：ウインドウのマテリアル上のサイドバー、不透明な内容、オプションのキューのペイン。
- プレーヤーは `zstack` に浮かぶ `material: "glass"` のバー。情報シートと設定シートは `view()` の別の枝にすぎない。
- `"settings": true` と、ユーザがアプリのアクセントを選べる設定シート（`macos.window.setAccentColor`）。
- 大量の読み込みが保存されている間、`fileprogress` で動くプログレスバー。
- 1 つのプレイリスト（`macos.archive`）または 1 曲の書き出しと読み込み。全部まとめての書き出しは システム設定 ▸ ストレージ ▸ データを書き出す… に任せる。
- オプションのフェード（設定）：一時停止と再開でフェードし、曲同士がクロスフェードする（`macos.audio` の `fade` / `crossfade`）。
- ページのヘッダはリストの上の `material: "bar"` レイヤー（`insetTop`）なので、行はすりガラスのタイトルの下をスクロールする。
- 起動時に、ユーザがオフにした必須の権限を求める（`macos.permissions.request`）。
- 独自のライト / ダーク / 自動の設定（`macos.window.setAppearance`）。
- 3 つのサイズの **最近再生した項目** ウィジェット（`macos.widgets`）：再生したものが変わるたびに「ミュージック」が公開し直し、その「再生」ボタンは「ミュージック」を開いてその曲を再生する。
- 曲とプレイリストは `macos.search` で Spotlight に登録される。選ぶと再生されるか、そのプレイリストが開く。
- メニューバー項目（`macos.statusItem`）が再生中のものを表示し、ウインドウが見えない間も再生 / 一時停止、次へ、前へを提供する。

### ブック

```text
plugin/examples/books/
plugin/examples/books.macos-app.json
```

電子書籍リーダー（`runtime: "native"`、同梱）です。EPUB の本と CBZ のコミック、コレクション付きの本棚、テーマ・フォント・目次・ブックマークを備えたページ送り式のリーダー、そして 1 日の読書目標。本はタイトルと著者で Spotlight に登録されます。読みかけの本、どこまで読んだか、今日の読書時間を表示する **続きを読む** ウィジェット（小と中）を提供し、その「続ける」ボタンはその本を開きます。

### ホシノ（デスクトップペット）

```text
plugin/examples/hoshino-pet/
  app.json
  src/index.html, src/style.css
  src/sprite.js        スプライトシート：クリップと 16 の視線方向
  src/behaviour.js     休む、見る、ウインドウに立つ、落ちる、歩き回る、運ばれる
  src/main.js          設定、メニュー、起動
  locales/*.json
  assets/sprites.webp  192 × 208 のコマが 8 × 11
  assets/icon.png, assets/status.svg

plugin/examples/hoshino-pet.macos-app.json
```

フレームなし、透明、フローティングで Dock アイコンのないウインドウに入った `runtime: "web"` アプリケーションです（`titlebar: "none"`、`material: "transparent"`、`level: "floating"`、`showInDock: false`）。

- 彼女は 1 枚のスプライトシートから `background-position` を動かして描かれます — 待機、手を振る、ジャンプ、左 / 右へ走るなど、それにあらゆる方向を見る 16 のポーズ。
- クリックを受け取るのは彼女だけ：すべてのポーズをスプライトシートのアルファチャンネルから一度だけ測り、`macos.window.setShape` でウインドウをその形に切り抜くので、彼女の横のデスクトップはクリックできるままです。
- 彼女を押すと `macos.window.beginDrag(event)` が始まります：横に運ばれると空中で走り、じっと持たれていると待ち、下ろされると着地します（またはデスクトップの端でつまずきます）。
- 彼女は物の上に立ちます（`macos.desktop`、権限 `windows`）：画面の下端、Dock の上端、すべてのウインドウ（Spotlight を含む）とデスクトップ上のすべてのウィジェットの上端と下端。足元に何もなければ、下にある次の縁まで落ち（`easing: 'in'` の `moveTo`）、ウインドウの上に立っているときはそのウインドウにくっつく（`macos.window.attach`）ので、ウインドウがドラッグされると一緒に動き、閉じられると落ちます。どちらの習性も、彼女のメニューのスイッチです。
- ときどき `macos.window.moveTo(x, y, { duration })` で少し歩きます — 立っているものに沿って、その両端より先には行かず — 届く範囲の別の縁に飛び移ったり（地面から Dock へ：上りは `easing: 'out'`、下りは `'in'`）、しぐさを 1 つ見せたりします：考え込む、身を乗り出してよく見る、手を差し出す、すねる（どれも彼女のメニューにもあります）。
- ポインタが近づいたときだけそちらを見ます（`macos.window.trackPointer`、権限 `pointer`）。デスクトップの離れた場所にあるときは、呼吸とまばたきを続けます。
- 彼女のメニューバー項目（`macos.statusItem`）と右クリックメニュー（`macos.ui.showMenu`、Web App でも使えます）は、サブメニューで、しぐさとリクエストによる散歩、彼女をクリックしたときにすること（1 つのしぐさ、またはランダムに 1 つ）、習性、3 つのサイズを提供します — さらに、呼び戻す、ユーザが複数ウインドウを許可していればもうひとり（`macos.instances.open`）、非表示、終了。彼女の位置と設定は `macos.storage` に保存されます。

すべてのアプリケーションと同じく、彼女は新しいタブが開いている間だけ動きます。すべての新しいタブに彼女がいるようにするには、設定 → アプリケーション で彼女の **新しいタブで自動的に開く** をオンにしてください（ユーザにしかできません）。

### 窓の外（デスクトップの天気）

```text
plugin/examples/outside/
  app.json
  src/index.html, src/style.css
  src/weather.js       Open-Meteo と、そのコードがシーンになる仕組み
  src/sky.js           キャンバス：パーティクル、物が降り積もる面、積もった雪
  src/main.js          ウインドウ、パネル、メニュー、ウィジェット、ピア
  locales/*.json
  assets/icon.png, assets/status.svg

plugin/examples/outside.macos-app.json
```

ウインドウがデスクトップ全体である `runtime: "web"` アプリケーションです。フレームなし、透明、`level: "desktop"`（すべてのウインドウの背後）、Dock アイコンなしで、どこでもポインタを受け取りません（`macos.window.setHitRegion([])`）— ただし設定パネルが開いている間のパネル上は例外で、そのために前面に出てきます（`setLevel('floating')`）。

- キャンバスは 1 枚で、そこに描くものは天気が許す限り少なくします：雨と稲妻は毎秒 30 フレーム、雪・花びら・落ち葉は 24、雲・霧・星は 12、ウインドウがドラッグされている間はその半分。決して動かないもの — 曇りの日の灰色、晴れた日の光、地面に沿った靄 — はキャンバスの背後の CSS 背景で、一度だけ描かれます。雲はそれぞれ、自分用の小さな絵に一度だけ描かれます。
- フレームにかかるコストと、ブラウザがフレームを落とす頻度を監視し、自分で段階を下げます — まずピクセルを減らし（1 ポイントあたり 1.5 → 1.25 → 1 デバイスピクセル）、次にパーティクルとフレームを減らします — 余裕があれば慎重にまた上げます。パネルの *低電力* は最も低い段階に固定します。
- それでも遅いマシンには負担が大きいので、ユーザが *今後表示しない* を選ぶまで、起動時にそのことを伝えます（`macos.dialog.confirm`）。
- 降ってくるものは、`macos.desktop.watch()`（権限 `windows`）から得た **面** に着地します：画面の下端、Dock の上端、すべてのウインドウの上端。それぞれシステムが報告する角丸の半径を持つので、吹きだまりは直角で終わらずに丸みに沿います。雨はそこで跳ね、雪は積もります — ゆっくりと、何分もかけて。
- すべての面がそれぞれの積雪を持ちます。ウインドウが動いた瞬間、その上のすべて — 雪、花びら、落ち葉 — が崩れて落ち、下にあるものの上に再び積もります。ウインドウの後ろに引きずられるものは何もありません。Dock の雪は、Dock がポインタの下で伸び縮みしても積もった場所に留まり、足場を失ったものは同じように落ちます。Dock の下の地面には何も積もりません。花びらと落ち葉は数秒しか残りません。
- 天気が変わると、新しいシーンにないものは 3 分の 1 秒で消えます — 空中のパーティクル、吹きだまり、地面の花びら。
- ウインドウの背後にあるので、描くものについて独自の遮蔽は要りません — 要るのは *着地する* ものだけです：雪片は、別のウインドウに覆われた縁には積もりません。
- `macos.fetch`（権限 `network`）によるライブの天気、傘としてのポインタ（`pointer`）、シーンを並べたステータス項目、ウィジェット。

### 紙ひこうき（未来の自分への手紙）

```text
plugin/examples/paper-plane/
  app.json
  src/index.html, src/style.css
  src/flight.js        ひこうきとしてのウインドウ：レイアウト、飛行、着陸
  src/main.js          手紙、書く、読む、郵便受け、通知
  locales/*.json

plugin/examples/paper-plane.macos-app.json
```

フレームなしでフローティングのアクセサリで、表示するものに合わせて大きさが変わります — 1 枚の紙、吹き出し付きのひこうき、`moveTo` で 1 フレームずつ動かされる飛行中のひこうき。

- 空中にある手紙は **スケジュールされた通知** でもあります（`macos.notifications.schedule`、id = 手紙の id）：手紙の期日になるとシステムがそれを表示し、新しいタブが開いていなくても構いません。開くとアプリケーションが起動し、そこでひこうきが着陸しに来ます。手紙を読む、削除する、送り直すと、その通知はキャンセルまたは置き換えられます。
- 手で投げる：`beginDrag` は、離した瞬間のポインタの速さ（`frame.velocity`）を付けて resolve し、それがひこうきの最初のひと押しになります。
- 実行中は、タイマーが期日の分にひこうきを着陸させます。ユーザの目の前ではそれで十分伝わるので、通知はキャンセルされます。
- システムの言語が変わると（`languagechange`）、画面上のすべてが書き直され、待機中の通知は新しい言語でスケジュールし直されます。
- `macos.context.launchReason` で、ユーザによる起動（ひこうきが自分から現れる）と、ユーザの *新しいタブで自動的に開く* 設定による起動（メニューバーで待つ）を区別します。

### 協力するアプリケーション：ホシノと窓の外

この 2 つは、マニフェストで互いの名前を挙げ（`"peers": ["outside-weather"]` / `"peers": ["hoshino-pet"]`）、`macos.apps` を通じて会話します。

| 送信元 | メッセージ | 相手がすること |
| --- | --- | --- |
| ホシノ | 起動時に `{ type: 'hello', head: { x, y, w } }` | 窓の外は天気を答え、彼女のウインドウの中で頭がどこにあるかを知る：雨はそこで跳ね、雪はそこに積もる |
| ホシノ | 歩いている間 `{ type: 'step', x, y, vx }` | 足元の雪が蹴散らされる |
| ホシノ | 落下やジャンプのあと `{ type: 'land', x, y }` | 着地した場所の雪が飛び散り、そこにあった花びらが舞い上がる |
| ホシノ | `{ type: 'shake' }` | 頭の上の雪が飛んでいく |
| 窓の外 | `{ type: 'hit', kind }` — 雨、雪、花びら、落ち葉が彼女に落ちてきた。頭の雪が深いときは `snowcap` | 見上げる、手を差し出す、何だったのか身を乗り出して見る — またはジャンプして雪を振り落とす |
| 窓の外 | 天気が変わったとき `{ type: 'weather', scene, night }` | 雨、雪、花びらに手を差し出し、雷でしょんぼりし、晴れると跳ねる |

どちらも相手に依存しません。窓の外がなければ、彼女は乾いたデスクトップのペットで、彼女がいなければ、雪は乱されずに積もったままです。どちらも `macos.desktop` から同じレイアウトを読むので、彼女が立っているウインドウは、雪が積もっているウインドウです。
