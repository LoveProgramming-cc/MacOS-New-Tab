# ランタイムとパフォーマンスのモデル、クラッシュの隔離

アプリケーション SDK ドキュメントの一部です — [README](../../README.ja.md) から読み始めてください。

## 10. ランタイムとパフォーマンスのモデル

SDK は、インストール済みでも閉じているアプリは継続的な描画コストが実質ゼロであるべきだ、という原則のもとに設計されています。

### インストール時の処理

アプリケーションの読み込み時に、検証、サニタイズ、コンパイルが行われます。コンパイル済みのパッケージはデスクトップの構成とは別にキャッシュされます。インストール済みのアプリを開くときに、パッケージのサニタイズが繰り返されることは通常ありません。

### アセットの遅延読み込み

大きなアセットのデータは別に保存され、参照されたときにだけ要求されます。画像を多く含むパッケージでも、アプリケーションの起動時にそれらすべてが自動的にデコードされたり転送されたりすることはありません。

### 専用のランタイムチャネル

実行中の各アプリケーションは専用の `MessageChannel` を受け取ります。グローバルな `window.message` リスナーはサンドボックスの起動にのみ使われ、通常の API 通信は専用ポートを使います。

### ホストが受け持つウインドウの合成

管理されたウインドウは、ホストの 1 つのガラスレイヤーを使います。ウインドウのドラッグ中は次のようになります。

- 移動はポインタキャプチャで駆動される。
- 見た目の動きは、アニメーションフレームごとに 1 回の `translate3d()` 更新で行う。
- 最終的な `left/top` の位置は、ドラッグが終わったときに確定する。
- プラグインの iframe は一時的にポインタ入力を受け取らなくなり、その上を通過してもホストのドラッグが奪われない。
- プラグインの CSS アニメーション/トランジションは一時停止する。
- アプリケーションのウインドウは、動いている間もシステムのウインドウと同じすりガラスを保つ。
- ドラッグはポインタが数ピクセル動いてから始まるので、タイトルバーを単にクリックしただけでは何も変わらない。

### 非表示時のサスペンド

アプリは表示状態の変化を受け取ります。厳格モードのインターバルは、アプリが非表示/最小化されている間、高頻度の処理を続けません。

### 作者向けの指針

なめらかなアプリのために：

- 可能な限り `runtime: "native"` を選ぶ。
- レイアウト用のプロパティや大きなフィルタではなく、`transform` と `opacity` をアニメーションさせる。
- 全面を覆う背景ぼかしのレイヤーを入れ子にして作らない。
- 常時動くポーリング用タイマーではなく、イベント駆動の更新を使う。
- ビュー全体を破棄して作り直すのではなく、既存の DOM/コントロールの状態を更新する。
- 同梱するラスター画像は、現実的な表示サイズにリサイズする。
- 非表示の間やホストがウインドウをドラッグしている間は、独自の描画を止める。
- 複数のコントロールが一緒に変わるときは、`macos.ui.batch()` で Native UI の変更をまとめる。

## 11. クラッシュの隔離

アプリのロジックは `plugin/app-runtime.html` の中で動き、新しいタブ本体の JavaScript コンテキストとは分かれています。捕捉されなかったエラーや処理されなかった rejection はホストに報告されます。ホストは失敗したランタイムを破棄し、そのアプリのウインドウに再読み込みの画面を表示します。

したがって、壊れたアプリケーションが、失敗したサンドボックスのタイマーやアニメーションをいつまでも動かし続けることはできず、デスクトップのシェルや他のアプリを終了させることもありません。
