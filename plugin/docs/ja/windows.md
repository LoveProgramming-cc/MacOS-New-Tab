# ウインドウ、アイコン、アクセントカラー、マテリアル

アプリケーション SDK ドキュメントの一部です — [README](../../README.ja.md) から読み始めてください。

## 4. ウインドウの取り決め

`window` は次のものをサポートします。

- `width`、`height` — ウインドウ外枠の初期サイズ。単位は **CSS ピクセル** で、ホストのタイトルバーを含みます。
- `minWidth`、`minHeight` — サイズ変更の下限。
- `resizable` — `false` でウインドウのサイズを固定します（`resize: "none"` と同じ）。
- `resize` — ユーザがドラッグできる辺：`"both"`（デフォルト）、`"horizontal"`、`"vertical"`、`"none"`。
- `maxWidth`、`maxHeight` — 手動のサイズ変更と拡大の上限。省略すると「画面が許す限りの大きさ」になります。
- `appearance` — `"system"`、`"light"`、`"dark"`：ウインドウが最初にとる外観。アプリケーションは実行時に `macos.window.setAppearance()`（後述）で変更でき、これによって自身の設定の中でライト / ダーク / 自動の選択をユーザに提供します。
- `material` — `"glass"`、`"solid"`、`"transparent"`。
- `titlebar` — `"standard"`（信号機ボタン、アイコン、タイトルのあるタイトル帯）、`"none"`（後述の *フレームなし、フローティング、アクセサリのウインドウ* を参照）、`"hidden"`（帯なし：信号機ボタンが左上隅に浮かび、内容が高さいっぱいに広がります。「システム設定」や Finder と同じです）。`"hidden"` のとき、ウインドウは内容の何もない面ならどこでもドラッグできます — コンテナ、スペーサー、ただのテキスト、`id` のない画像、`video` ノード — ただしコントロールでは決してドラッグされません。ドラッグは、それが始まった面へのクリックとしては数えられません。
- `titlebarHeight` — 32–72 CSS px（標準のタイトルバーのみ）。
- `borderRadius` — 8–28 CSS px。デフォルトの 12 はシステムのウインドウの角丸です。
- `showTitle` — 標準のタイトルバーにアプリのアイコン/タイトルを表示するかどうか。

- `level` — `"normal"`（デフォルト）、`"floating"`（どの通常ウインドウが前面にあっても、すべての通常ウインドウより上に留まる）、`"desktop"`（すべての通常ウインドウの背後、壁紙・デスクトップのアイコン・ウィジェットの上に留まる — 天気、デスクトップに描かれた時計）。どちらのレベルのウインドウも、Launchpad が開いている間は脇に退き、Mission Control には含まれません。`macos.window.setLevel(level)` で実行中に変更できます。デスクトップレベルのウインドウが自分のパネルを開くときは、パネルが開いている間だけ `"floating"` に上がります。
- `showInDock` — `false` にすると、アプリケーションは *アクセサリ* になります。実行中も Dock アイコンがなく、そのウインドウをクリックしてもメニューバーは渡されません。到達できるようにするにはメニューバー項目（`macos.statusItem`、権限 `statusItem`）が必要です。それがない間 — 権限がオフ、または項目がまだ設定されていない — は Dock に通常どおり表示されるので、いつでも見つけて終了できます。

### フレームなし、フローティング、アクセサリのウインドウ

`titlebar: "none"` は、タイトルバーとウインドウのボタンを完全に取り除きます。ホストは何も描きません。`material: "transparent"` と組み合わせると、ウインドウはアプリケーションが描くものだけになり、枠も影もありません。このようなウインドウは

- 40 × 40 まで小さくでき、ユーザはサイズを変更できません（`window.resize()` は引き続き使えます）。
- どこへ動かされても、またブラウザのウインドウが小さくなったときも、常にデスクトップ上、メニューバーの下に完全に収まります — その場合は中へ戻され、`moved: true` の `screenchange` を受け取ります。
- アプリケーションが動かします：`pointerdown` から `macos.window.beginDrag(event)` を呼ぶと、ユーザは押したものをつかんでウインドウを運べます。`macos.window.moveTo(x, y, { duration })` は移動（または滑走）させます — §7 の `macos.window` を参照。
- 「ウインドウ」メニューからは最小化も拡大もできません。`macos.window.minimize()` / `focus()` で隠したり表示したりし、`close()` で終了します。

デスクトップペットはこの 3 つをすべて組み合わせます。

```json
"window": { "width": 106, "height": 114, "titlebar": "none", "material": "transparent", "level": "floating", "showInDock": false }
```

**形状。** ウインドウは長方形で、何もしなければその全体がポインタを受け取ります — 透明な部分も含めて。フレームなしのウインドウは、`macos.window.setShape(rects)` で実際に覆っている範囲を伝えられます。ウインドウ座標の `[x, y, width, height]` 矩形のリスト（最大 400 個）です。ウインドウはそれらの和集合に切り抜かれ、それ以外の場所へのクリックは下にあるもの — デスクトップ、そのアイコン、別のウインドウ — に届きます。絵が変わるたびに呼び直してください（ペットなら、ポーズが変わるたび。すでに持っているのと同じ形状はホストが無視します）。`setShape(null)` でウインドウ全体が再び対象になります。アプリケーションが形状を設定していない間は、ウインドウ全体が対象です。

```js
// ポーズの 1 コマ。8 px のブロック単位でアルファから一度だけ測り、つかみやすいよう 1 ブロック広げたもの
await macos.window.setShape([[12, 0, 30, 8], [6, 8, 44, 60], [14, 68, 28, 40]]);
```

完全な例は §12 の *ホシノ* を参照してください。スプライトシートのすべてのポーズを、画像のアルファチャンネルから測っています。

**ポインタを受け取る場所。** 形状はウインドウを切り抜きます — その外側は描画もされません。`macos.window.setHitRegion(rects)`（Web App）は絵には触れず、ウインドウがどこでポインタを受け取るかだけを伝えます。列挙した `[x, y, width, height]` 矩形（最大 64 個）です。それ以外の場所では、ウインドウがそこに描画していても、クリックは下にあるものに届きます。`[]` はウインドウ全体をクリック透過にし、`null` は再びすべての場所でポインタを受け取るようにします。

```js
// デスクトップ全体に降る雨と、クリックできる 1 枚のパネル
const r = panel.getBoundingClientRect();
await macos.window.setHitRegion(panel.hidden ? [] : [[r.left, r.top, r.width, r.height]]);
```

ウインドウが描くものそのものであるときは `setShape` を（ペット：切り抜くことでレイヤーも小さく保てます）、クリックされたい範囲よりも広く描くときは `setHitRegion` を使ってください（天気、カードの周りの柔らかい影、吹き出し）。クリック透過の部分の上でも、`trackPointer` のポインタ位置は届き続けます。

赤、黄、緑のボタンはホストのものです：閉じる、Dock アイコンへの最小化（スケールエフェクト）、拡大／縮小。拡大は、ウインドウをサイズ変更のルールが許す最大のサイズにします — 自由にサイズ変更できるウインドウならメニューバーと Dock の間の領域全体、`"vertical"` のウインドウなら高さいっぱいだけ、そして `maxWidth` / `maxHeight` を決して超えません — その領域を埋めない方向は中央に寄せます。まったくサイズ変更できないウインドウでは、緑のボタンが無効になります。拡大されたウインドウをドラッグすると、ポインタの下で元のサイズに戻ります。最小化または非表示のアプリは動き続けます。ホストはまた、すべてのアプリのメニューバーに **ウインドウ** メニュー（しまう、拡大／縮小）を追加します。

`moveTo(x, y, { duration, easing })` は `easing: 'linear'`（デフォルト）、`'ease'`、`'in'`（落ちるもののように速度を増す）、`'out'`（上に投げられたもののように速度を失う）を受け取ります。ウインドウは別のウインドウと一緒に移動することもできます — `macos.window.attach`、§7 の `macos.desktop` を参照。

### アプリケーションのアイコン

アイコンは macOS のアイコングリッドに沿って描いてください。正方形のキャンバスで、絵（角丸の正方形）がその約 80% を占め、中央に置かれます — 1024 px のうち 824 です。Launchpad、Dock、Finder は、アプリケーションのアイコンを内蔵のものと並べて原寸で表示するので、キャンバスの端から端まで埋めたアイコンは大きすぎて見え、余白の多すぎるアイコンは小さく見えます。

### アクセントカラー

システムのアクセントは、固定の 1 色か **マルチカラー** のどちらかです。マルチカラーでは、各アプリケーションが自分のアクセントを使います。マニフェストの `accentColor`（`blue`、`purple`、`pink`、`red`、`orange`、`yellow`、`green`、`graphite`、または `#rrggbb`。デフォルトは青）で、アプリは実行時に `macos.window.setAccentColor()` で変更できます。システムの色が固定されているときは、すべてのアプリケーションがその色を使い、アプリ自身の選択は保持されますが表示されません。

アクセントは、選択、プライマリボタンと色付きボタン、フォーカスリング、プログレスバー、リンク、色付きのリストアイコン、そして `accent` カラートークンを決めます。カラートークンとしての `blue` は青のままです。ホストはアプリごとのアクセント設定を提供しません。ユーザに選ばせたいアプリは、それを自身の設定に組み込み（§8 の *設定…* を参照）、選択を自分で保存します。

```js
macos.context.accentColor    // '#ff5257' — 現在有効な色
macos.context.accentSetting  // 'multicolor' または固定されたシステムカラーの名前
await macos.window.setAccentColor('purple');   // または '#8844ee'。null でマニフェストのアクセントに戻る
macos.on('accentchange', ({ accentColor, accentSetting }) => {});
```

`appearance: "system"` はデスクトップに従います。計算機のようなアプリケーションは、恒久的に `"dark"` を要求できます。

### マテリアルの持ち主

**負荷の大きい壁紙の背景ぼかしは、アプリケーションの外側のウインドウが持ちます**。アプリの内容は、通常はルートを透明にしてください。アプリの中に、ウインドウ全面の 2 つ目のぼかしを描かないでください。

ウインドウの内側では、ネイティブアプリは SwiftUI アプリと同じように、コンテナごとに `material` で面を選びます。

| `material` | 面 |
| --- | --- |
| `sidebar` / `clear` | 自身は何も持たない — ウインドウのマテリアル（すりガラス越しの壁紙）が透けて見える |
| `content` | 不透明なウインドウの背景。「システム設定」の右側と同じ |
| `glass` | アプリ自身の内容の上に浮かぶすりガラスのパネル（プレーヤーバー、シート） |
| `bar` | 自身のウインドウの内容の上にあるすりガラスのバー：ページがその下をスクロールするページタイトルやツールバー。ウインドウの不透明な下地の上でその内容をぼかし、デスクトップをぼかすことはない |

`bar` は浮いているので、ページの上にある `zstack` のレイヤーとなり、ページはその分の場所を空けます。

```js
{ type: 'zstack', children: [
  { type: 'list', id: 'songs', insetTop: 62, items },                       // 行はバーの下から始まり、バーの下をスクロールする
  { type: 'stack', material: 'bar', height: 62, alignSelf: 'start', justifySelf: 'stretch', children: [title, search] }
] }
```

`list` / `table` は `insetTop`（と、下に浮かぶバーのための `insetBottom`）を受け取り、行はバーの下から始まります。`scroll` は同じ 2 つのプロパティを受け取り、スクロールバーがバーにかからないようにします。内容にはその分のパディングを自分で与えてください。「システム設定」、Finder、「ミュージック」、「ブック」はこの方法でヘッダを描いています。

`split` コンテナは、通常の配置を自動的に適用します。最初の子はサイドバー（ウインドウのマテリアル、右側に細線）、それ以降の子はすべて不透明な内容、3 番目の子には左側に細線が付きます（インスペクタ）。ペインに `material` を設定すると上書きできます。内容ペインに `material: "clear"` で全面ガラスのウインドウに、サイドバーに `material: "content"` でガラスのまったくないウインドウになります（または `window.material: "solid"` を使います）。

サイドバーのペインは、内容がウインドウより高いときに自分でスクロールします。譲れる部分 — 内部でスクロールする `list` — が先に縮み、固定の高さの内容が収まらなくなって初めてペインのスクロールバーが現れます。これについて宣言するものは何もありません。

ぼかしがオフになっている場合（「透明度を下げる」、またはすりガラスの代わりに透明表示）、`glass` パネルは不透明な浮き上がった面になります。スクロールする内容の上にぼかしのないガラスがあると読めないからです。アプリはこのために何もしません。

開発者モード → **すりガラスの代わりに透明表示を使用** が有効なとき、ホストは同じ意味のマテリアルを保ちつつ、背景サンプリングを無効にします。したがって、アプリは独自の特別なパフォーマンスモードを実装しなくても、見た目の一貫性が保たれます。

「透明度を下げる」/「コントラストを上げる」が有効なときも、ホストは同様にマテリアルを一元的に変更します。
